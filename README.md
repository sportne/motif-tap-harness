# Motif Tap Harness

**Motif Tap Harness** is a starter project for turning manual workflows in legacy X11/Motif applications into maintainable Python GUI tests without requiring a large application rewrite.

The project is designed for applications built with Xt/Motif, including many applications generated by GUI builders such as Builder Xcessory. The central idea is simple:

```text
Record the user's X11 input with Xnee
+ observe the live Xt/Motif widget tree with a tiny preload hook
= generate Python tests that click widget paths instead of screen pixels
```

Raw record/replay tools are useful, but they often produce fragile tests because they remember absolute screen coordinates. Motif Tap Harness tries to lift those recordings into semantic actions:

```python
app.click("myApp.mainWindow.form.applyButton")
app.type_text("/tmp/input.dat")
app.press("Return")
```

Instead of:

```text
move mouse to root coordinate 842,416
button 1 press
button 1 release
```

That difference is the purpose of the project. The generated tests can survive window movement, different placement by the window manager, and many small layout changes because the test runner asks the application where the widget is *now* before clicking it.

---

## Project status

This repository is a **starting point**, not a drop-in commercial testing product. It contains:

- A C `LD_PRELOAD` hook prototype for Xt applications: `c/xttap.c`.
- A Python test harness that can locate widgets from a live JSON state file and drive X11 with `xdotool`.
- A translator that maps normalized Xnee events to widget-aware Python test code.
- CLI commands for recording, normalizing, translating, and inspecting state.
- Example recordings and generated tests.
- Documentation describing the intended user experience, architecture, limitations, and test automation approach.

The first milestone is not perfect automation. The first milestone is to automatically convert most recorded clicks into stable widget-path actions and clearly mark the rest for human review.

## Prerequisites

For development:

```text
Python 3.10+
pytest, for running the included unit tests
```

For running against a real Motif application:

```text
X11 session or Xvfb
```

```bash
sudo apt-get install python3 python3-venv python3-pip gcc make \
  libxt-dev libx11-dev xdotool xnee xvfb x11-utils
```

## Quick start for the Python pieces

Create a virtual environment and install the package in editable mode:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
pytest
```

You should see the included tests pass. These tests exercise the translator and widget hit-testing logic without needing a real Motif app.

## Build the Xt hook

```bash
make -C c
```

This should produce:

```text
c/libxttap.so
```

The preload hook is intentionally small. It observes Xt widgets and writes:

```text
latest-state.json   # current widget tree for the replay harness
widgets.jsonl       # timestamped snapshots for the translator
```

Use it manually like this:

```bash
MOTIF_TAP_STATE=/tmp/motif-tap/latest-state.json \
MOTIF_TAP_LOG=/tmp/motif-tap/widgets.jsonl \
LD_PRELOAD=$PWD/c/libxttap.so \
./my_motif_app
```

Then inspect the state:

```bash
motif-inspect-state /tmp/motif-tap/latest-state.json
```

## Record a workflow

```bash
motif-record \
  --name open_valid_file \
  --tap-so ./c/libxttap.so \
  --app ./my_motif_app --test-mode
```

The recorder launches the application with the Xt hook active and starts `cnee` recording. You perform the workflow manually, then press Enter in the terminal to stop recording.

The output goes to:

```text
recordings/open_valid_file/
  meta.json
  latest-state.json
  widgets.jsonl
  xnee.xns
  xnee-human.txt
```

## Normalize the Xnee recording

Xnee output formats can differ across builds and command-line options, so this repo uses a simple normalized JSON Lines event format internally.

```bash
motif-normalize-xnee \
  recordings/open_valid_file/xnee-human.txt \
  --out recordings/open_valid_file/events.jsonl
```

The normalizer is intentionally conservative. If your local `cnee --human-printout` format differs, update `src/motiftap/xnee_normalize.py` once and keep the rest of the pipeline stable.

The normalized event format looks like:

```json
{"t": 0.210, "kind": "button", "phase": "press", "button": 1, "x": 842, "y": 416}
{"t": 0.290, "kind": "button", "phase": "release", "button": 1, "x": 842, "y": 416}
{"t": 0.500, "kind": "key", "phase": "press", "key": "Return"}
```

## Translate the recording into a Python test

```bash
motif-translate \
  recordings/open_valid_file \
  --out tests/test_open_valid_file.py \
  --app ./my_motif_app --test-mode
```

Example generated output:

```python
from pathlib import Path
from motiftap.harness import MotifApp


def test_open_valid_file():
    with MotifApp(["./my_motif_app", "--test-mode"]) as app:
        app.wait_for_idle()
        app.click("myApp.mainWindow.form.openButton")  # HIGH: XmPushButton
        app.type_text("/tmp/input.dat")
        app.press("Return")
        app.wait_for_widget("myApp.completeDialog.okButton")
        app.click("myApp.completeDialog.okButton")

        assert Path("/tmp/output.dat").exists()
```

The translator marks uncertain actions with comments such as:

```python
app.click_relative("myApp.mainWindow.drawingArea", 183, 72)
# LOW: parent-relative fallback; review manually
```

The test author reviews those lines and adds real application assertions.

## Run generated tests

In a real X11 session:

```bash
pytest tests/test_open_valid_file.py
```

In CI or headless automation:

```bash
xvfb-run -a pytest tests/test_open_valid_file.py
```

For deterministic GUI tests, keep the environment stable:

```text
same resolution
same fonts
same locale
same color depth
same Motif resource files
same or similar window manager behavior
```

## Test automation approach

The recommended strategy is layered:

1. **Use Xnee only to capture manual workflows.** Do not treat raw Xnee recordings as the permanent test artifact.
2. **Use the Xt hook to map screen coordinates to widget paths.** This turns fragile coordinates into stable semantic actions.
3. **Generate Python tests.** The tests become readable, reviewable, and version controlled.
4. **Replay through the live widget map.** At runtime, `app.click(path)` resolves the current geometry of the widget.
5. **Assert application behavior.** Prefer output files, logs, database state, dialogs, and domain results over screenshot matching.
6. **Capture diagnostics on failure.** Save screenshots, widget state, window trees, stdout/stderr, and application logs.

See [`docs/test-automation-approach.md`](docs/test-automation-approach.md) for details.

## Why this instead of raw Xnee replay?

Raw Xnee replay is useful for quick demos and smoke tests, but mouse-heavy recordings frequently break when:

- the window moves,
- fonts change,
- a dialog appears in a different location,
- the window manager changes decorations,
- timing changes,
- the UI layout shifts slightly.

Motif Tap Harness uses Xnee as the capture mechanism, then converts the recording to a maintainable test script.

---

## Why this instead of changing the application heavily?

The hook is deliberately external. For many applications, the only test-specific runtime change is:

```bash
LD_PRELOAD=/path/to/libxttap.so
```

If you are allowed to make small source changes, a linked-in version of the same hook is cleaner and more reliable than `LD_PRELOAD`. The Python pipeline does not care which approach produced `latest-state.json` and `widgets.jsonl`.

---

## Limitations

This approach works best for conventional Xt/Motif applications. It is less effective for:

- statically linked binaries,
- setuid/security-restricted executables that ignore `LD_PRELOAD`,
- custom direct-Xlib drawing with no useful Xt child widgets,
- complex drag-and-drop workflows,
- OpenGL/visualization canvases where semantic assertions require application-specific helpers,
- tests that depend on exact rendering rather than behavior.

See [`docs/limitations.md`](docs/limitations.md).

## Roadmap

The intended next steps are:

- Harden the C hook against more Xt initialization patterns.
- Add local Xnee parser profiles for common `cnee` versions.
- Add text coalescing from keypress streams.
- Add a small HTML translation report.
- Add support for stable widget aliases.
- Add optional visual assertions for drawing-area-heavy applications.
- Add a linked-in hook mode for teams that can make a small application startup change.
